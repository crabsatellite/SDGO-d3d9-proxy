# 每日双倍时间（Beta）

`daily_rewards` 是对战服务器 Mod。启用后，每天按 **BattleServer 所在机器的本地时间**，
在 **18:00（含）至 22:00（不含）**将正常战斗结算的 **G 币、驾驶员经验/军衔星数、机体经验**翻倍。
玩家不需要安装客户端 Mod，也不需要修改客户端时间或使用特殊启动器。

按生成该玩家最终结算的时刻判断，开局时间不决定加成。原生活动、道具等加成先按游戏自身规则计算，
本 Mod 对原先的最终收益应用一次 ×2；对应差额并入原生的活动奖励明细，随后由游戏继续处理机体经验、
数据库请求和客户端结算包。修理费、能量消耗、胜负、评级、竞技分与随机掉落不翻倍。
额外的任务/成就奖励、充值、商城、赠送与 GM 发币不属于正常战斗结算。

## 安装和配置

需要随本 Mod 更新的 **1.1.4 或更新框架**，以及支持的
`BattleServer-548A891D-0046C000`。服主自行退出准备更新的对战服务器，再使用该版本发行包安装。

更新前备份现有框架、符号表和配置。安装器会保留其他 Mod 目录，但会更新包内同名文件。
如果现有符号表包含自定义 Mod 的额外条目，安装后、启动前将这些条目合并回对应主机符号表，
保留本版本新增的 `battle.reward.final.*` 和 `battle.reward.layout.*` 各十项；
遇到同名但内容不同的条目应先核对实际 EXE。其他 Mod 的 DLL、数据和设置应保留。

安装命令（在发行包目录运行）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File install_server.ps1 -ServerRoot "D:\SDGO\Server" -Role Battle
```

在每个对战服务器目录中，将 `sdgo/mods/daily_rewards/config.example.ini` 另存为 `config.ini`：

```ini
[settings]
StartTime=18:00
EndTime=22:00
Trace=0
```

没有 `config.ini` 时沿用清单中同样的默认设置。有该文件则整份采用其中的 `[settings]`。
默认清单启用此 Mod，实际是否生效还受玩法分类、功能组和单个 Mod 开关控制。
修改设置后重启相应 BattleServer；正常的每日开始/结束会自动按结算时钟判断，无需定时重启。

时间严格使用 `HH:MM`，支持分钟和跨午夜，例如 `23:30` 至 `01:15`。
开始和结束相同，或小时/分钟无效时拒绝加载，不自动解释为全天。
采用服务器系统时区；分布在多台机器时，服主应统一各机器的时区和时钟。

`Trace=1` 在日志中记录最初 32 次生效结算的三项前后值，不记录玩家账号或密码。
启动日志应出现 `loaded Daily double battle rewards (Beta)`，以及配置的本地时间段。

## 关闭和卸下

关闭服务器后，在 `sdgo/sdgo.ini` 中设置以下任意开关：

```ini
[features]
daily-rewards=0
```

也可在 `[mods]` 下设置 `daily_rewards=0`。`[categories] gameplay=0` 会同时关闭这一类玩法扩展。
只卸除此功能时，关闭服务器后移走 `sdgo/mods/daily_rewards/`，保留公共框架和其他 Mod。
通用安装器的 `-Uninstall` 卸载整套框架，不是单独卸除此功能。

## 范围与验收

覆盖当前服务器结算分发器的全部十条原生路径：个人房、普通团队、Tag、死亡/Grid、队长、
原生 AI/战舰、模式 13/14 和任务模式 5/8/10。原生不发奖的情况仍不发奖。
原生等级/奖励规则继续执行；单次结算字段为 16 位，翻倍超过 `65535` 时饱和到该上限，防止回绕。

**Beta：尚需真实账号和完整对局手动验收。** 自动测试覆盖时间边界、跨日、溢出、八类真实 core/Mod
夹具情形和全部十个结算位置；也检查 CPU、浮点/SIMD 状态及无关数据的保留。
测试不启动游戏、不登录账号、不向实际数据库发奖。实测时应核对 G 币余额、军衔星数、机体经验和结算明细，
尤其是已有原生活动/道具加成、满级机体、失败任务和时段边界。

## 手动验收

1. 查看 `sdgo/logs/sdgo.log`，确认此 Mod 和原有 Mod 加载成功，并核对日志中的时间段及服务器时区。
2. 默认时段外要立即实测时，先备份 `config.ini`，临时配置一个包含当前服务器时间的时段，
   再重启参与测试的 BattleServer。不要修改系统时钟；所有承接测试对局的 BattleServer 应使用相同设置。
3. 设置 `Trace=1` 并重启后，最初 32 次生效结算会记录同一次结算的三项前后值，例如
   `pilot EXP 100->200, G 200->400, unit EXP 300->600`。
   对照本次结算的总数及活动奖励明细；不同对局的原生收益可能不同，不直接用两场总数相除判断。
4. 手动核对 G 币余额、军衔星数、机体经验，重登后再次确认持久化；另测任务与 PvP、失败任务、
   原生加成、满级机体以及开始/结束边界。原生不发奖的情况不应因此获得奖励。
5. 实测后恢复 `18:00` 至 `22:00`，按需改回 `Trace=0`，重启改过配置的 BattleServer。

启动及离线测试通过只确认安装和结算钩子可用，实际账号收益、客户端显示和重登结果仍以手动验收为准。
