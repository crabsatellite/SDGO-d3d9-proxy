# 活动扭蛋币种显示修复

`capsule_currency_fix` 是独立客户端自动修复，位于 Mod Manager 的「修复归档」。
它不属于商城汉化，也不替换普通商城的 GB / MB 编码。

## 这次失败的两个原因

用户提供的实际截图显示，9301 的列表和购买确认框仍为 `99 G币`。
2026-11-01 只读核对本机实际环境时，主客户端没有安装本 Mod，运行日志也没有它的加载和纠正记录。
原服配置表 `tbl_ItemMachinePrice` 的 9301 为 `Type=2, Price=99`，正确显示是 **99 代币**。
列表中的 9201 为 10000 G币，9101 为 3 代币，新增收藏机 990001 为 100000 G币，这些保持原样。

此外，原生活动列表与购买确认框不共用显示副本。列表点击仅传递 MachineID；
确认框会重新枚举 GridData type `0x3C`，从注册记录的 `+9` 选择币种和钱包，
从 `+15` 取价格。原来的只改列表副本方案即使安装，也修不到确认框。

1.0.1 在完整检查列表后，以 Grid ID `145093` 调用原生查找，要求源记录与列表副本的
179 字节完全相同且均可写，才各修正一个币种字节。客户端内存注册记录随之为 Type2，
确认框会读取它。磁盘 GDT、catalog overlay 和服务端不改；不写玩家钱包数值。

此前的单元 fixture 只证明一条记录检查和修改范围，没有证明确认框路径或补丁已安装到实际客户端。
安装、进程加载、进入活动页执行纠正、真实画面和实际扣款分别验收。

## 安装与检查

客户端先安装基础框架。关闭这个游戏副本后，在 Manager 选择相应客户端，用「导入客户端配置包」
导入 `SDGO-CapsuleCurrencyFix-1.0.1.zip`，在「修复归档」确认活动扭蛋币种显示修复已启用，重新启动游戏。
如果本机以首次增量方式预装文件，正在运行的游戏不会热加载，也需正常关闭再启动。

进入「活动扭蛋机」后检查：

1. 93 号机列表为 **99 代币**，其他已正确币种不变。
2. 打开它的购买确认框，币种、价格及当前/预计余额应使用代币。只打开和取消，无需抽取即可检查显示。
3. 客户端 `sdgo/logs/sdgo.log` 应同时有 `capsule_currency_fix: loaded` 和
   `activity machine 9301 display currency corrected`（或 `already type 2`）的结果行。
   仅出现 DLL 加载不代表页面执行成功；`refused` 记录需继续调查。
4. 要验收真正扣款，由用户自行手动抽取并核对代币与其他余额；程序和测试不操作真人账号。

本次不重启游戏服务、不改服务器价格或币种、不进行抽奖、不自动退款。
已有客户端补丁、作者配置、共享目录和游戏资源原文件保留。

## 自动验证边界

- 既有逻辑测试验证单字节修改、重复/错误记录拒绝和原生 93 记录填充。
- 新增测试实际加载 DLL，调用其真实活动列表 Hook，验证 94 机台/96 槽与收藏机共存，
  列表副本和内存注册记录各只改 9301 的一个币种字节；磁盘源、价格、其他机台保留。
  覆盖二次加载幂等，以及注册记录查错/数据不同/价格改变时拒绝两个写入。
- 独立 ZIP 经 Manager 标准导入、修复归档和文件哈希读回验证。
- 原生符号字节离线核对；实际列表、确认框、余额预览和手动抽取仍按上面的真人步骤验收。
