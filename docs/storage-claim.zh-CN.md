# 保管库一键领取（Beta）

客户端 Mod `storage_claim` 在保管库两个页签的右侧添加「一键领取」。使用当前客户端原生皮肤、文字和点击事件，玩家不用补素材、填账号或启动 Manager 后台。

0.1.1 修复大厅状态误判导致的无响应，以及鼠标移入/移出取消确认状态的问题。使用原启动器进入游戏即可，页面接入和点击另有日志记录，不以「Mod 已加载」冒充实际交互成功。

## 使用

1. 进入保管库，选择要领取的物品或礼物页签。
2. 点击「一键领取」，再点击「确认领取」。整个批次只确认一次；领取限时物品可能开始计算使用时间。
3. 自动处理当前页签的全部分页，底部显示已确认数量。领取中按钮变为「停止领取」。

每次只发送一笔原生请求：读取新列表、服务器预检、领取、等待原生到账回执，再读新列表。
普通物品领取后记录会移走，因此从第一页继续；礼物保留原信件，跳过已领取记录并向后翻页。
使用完整实例 ID；相同物品的不同奖品记录分别领取，不按名称或格号猜测。

遇到容量不足、服务器拒绝、需要选择内容的礼包、断线、超时或离开页面时停止。
选择礼包请用原生按钮单独操作，本 Mod 不代选。停止只阻止后续请求，已经发出的领取以服务器最终结果为准。
结果未确认期间不重新发起批次，不自动重发领取请求；请等待回应，必要时重新登录核对。
领取期间保留关闭按钮，暂时拦截原生行操作、分页和页签切换，避免与批次交叉。

## 安装与设置

完整框架包包含该玩法扩展，Base 包不包含。也可关闭目标客户端，在统一 Mod Manager 中导入专用增量 ZIP，再正常启动游戏。
只需客户端部分，不需要服务器 Mod、SQL 权限、HTTP 服务或专用启动器。
支持 `GOnline-54BE1568-00C97000`；代码地址、原生布局或皮肤不匹配时不显示新增入口，保留原有领取方式。

Manager 可停用本功能。开发模式提供 `RequestIntervalMs=200`、`ReplyTimeoutMs=10000`、`MaxClaims=5000`；正常使用不必调整。
原生礼物页码最多 255 页，超过时停止提示，不会页码溢出。达到单批上限可以重新发起批次。

## 验证边界

本地读取了 `1396.uir`：450×540，页签在 y=64，新增按钮在 x=291、y=64，状态在 y=520，不覆盖原列表、分页、过期提示或关闭按钮。
普通物品与礼物复用原生服务器预检和发放协议。取消后迟到的预检回执由 Mod 消费，不交给原生自动领取分支。
领取成功仍交原生处理器发放和刷新库存，Mod 不写数据库。

自动测试使用合成客户端缓存、物品列表、网络回执和原生 UI 接口替身，覆盖分页、逐笔确认、容量拒绝、手动选择、取消、超时、迟到回包和初始化失败。
未自动启动游戏或领取真实奖品。真人需验收按钮位置/文字、普通物品与礼物到账、限时物品和容量不足行为。
