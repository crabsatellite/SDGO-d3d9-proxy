# 商城窗口与显示补丁手动测试

## 打开管理窗口

双击桌面「SDGO 商城管理」，或 `SDGO Mod Manager.exe`。
本机服务端和客户端会自动选中；点击「连接 / 刷新」可读回本服物品和商品状态。
当前只显示本 catalog 管理的商品，原版商品不在这个编辑列表里。

## 显示补丁

1. 重新启动主客户端，进入商城，找到原商品 `DUAL GUNDAM ASSAULT SHROUD + BUSTER GUNDAM`，
   ProductId=1010465、9900 MB。
2. 看悬停详情、购买选项、可用时的赠送选项，原问号期限应明确显示「租赁 7 天」。不用确认购买即可检查文字。
3. 再看永久机体，销售选项应为「永久」，价格和币种保持原值。
4. 若有问题，检查客户端 `sdgo/logs/sdgo.log` 中 `shop_labels` 的加载或失败信息。

补丁处理销售选项的期限和标签，不修复已在数据库丢失的任意商品名或聊天编码。
活动扭蛋 GB/MB 问题由扭蛋机模块处理。

## 新增、查询、编辑、删除

1. 点击「新增商品」，搜索 `Zaku II`，选永久类别。名称填 `SHOPTEST GB`，价格 500，币种 GB，保存草稿。
2. 再新增一件相同永久机体，名称 `SHOPTEST MB`，价格 500，币种 MB。
3. 新增租赁类别 `DUAL GUNDAM ASSAULT SHROUD + BUSTER GUNDAM`，名称 `SHOPTEST RENTAL`，
   价格 500 MB，租期 7 天。界面应自动显示「租赁 7 天」，不能改成永久标题来隐藏租赁属性。
4. 点击「应用到商城」，核对目标区服和三件商品后确认。重新打开游戏内商城，搜索 `SHOPTEST`。
   两件永久商品分别为 500 GB、500 MB，租赁商品为 500 MB / 7 天，物品图片应与所选类别一致。
5. 在窗口搜索 `SHOPTEST GB`，点击「编辑」把价格改为 600，保存并应用。重开商城应变为 600 GB，
   其他两件不变。主列表「服务端状态」应从待应用修改变成已上架。
6. 选择商品点「上架 / 下架」后应用，确认下架后从游戏商城消失；再次切回上架并应用后可恢复。
7. 选择三件测试商品逐一「删除」，再应用。重开商城后它们应消失；原版商品保留。
   切换列表筛选到「所有商品 / 已删除」可以查看保留编号的定义。

本机另有 `test-offers.json`，也可通过「导入商品配置」一次导入预先准备的三件示例。
导入后仍是草稿，点「应用到商城」才真正上架。若本机已添加自己的商品，优先手动新增，避免替换当前销售方案。

要验证实际扣款和发货，用自己选定的测试账号购买 GB、MB 商品，核对前后两种余额和仓库期限，
应只扣对应币种。工具不会替你登录、购买或修改玩家余额。手动购买会正常扣款和发货，不自动退款或收回物品。

## 配置分发

点「导出商品配置」，在另一个独立管理目录导入，应保留商品定义但不包含宿主数据库设置和本机路径。
成功应用后点「导出玩家显示配置」，将 display.ini 通过独立 ShopLabels 补丁导入到玩家客户端。
玩家客户端和宿主需要一致的原生资源；界面不会向朋友分发 SQL 密码。

若结果不符合预期，提供商品标题、是悬停/购买/赠送窗口、对应截图和 shop_labels 日志行。
不要发送宿主数据库 INI 或账号密码。真人登录、游戏画面和实际发货仍由用户手动验收。
