# 战斗奖励：已确认规则与原生结算

本次提供 Beta 原生结算 Mod、GB/MB 入账与余额通知、辅助端口倍率控制和计算器。
完整安装、启动、恢复与卸载见[部署教程](battle-rewards.zh-CN.md)。真实账号对局和 HUD 仍由服主手动验收。

## 已确定的规则

- 这里的两种货币按 GB（G币，钱包 `f_GP`）和 MB（M币，钱包 `f_GC`）处理。
- 标准对战中的 AI 队友、AI 敌人与纯真人对战同档，不按机器人数量打折。
- 每多一名有效真人乘 1.1，使用乘法复利。AI、观战者不计入真人数。
- 基础倍率和双倍时段相乘：十倍乘双倍是二十倍，再叠加真人人数。
- 胜负保底之外，个人击杀、实际伤害与助攻参与结算；任务增加小怪和 Boss 贡献。
- 对战收益整体显著高于任务，MVP 在对战中额外获得 MB。

## 统一公式

```text
最终 GB/MB = 向下取整一次(
    一倍奖励 × 基础倍率 × 活动倍率 × 1.1^(有效真人数−1) × 有效参战时间系数
)

对战一倍奖励 = 胜负保底 + 封顶后的个人贡献 + 对战 MVP 奖励
任务一倍奖励 = min((通关/失败保底 + 封顶后的任务贡献) × 难度系数, 任务一倍总额上限)
```

真人加成同时用于对战和任务。以全房间唯一、有效的真人账号数计算，不只看本方队伍。
同账号重连不重复计数；完成有效参战的玩家不因结算瞬间暂时离线就自动丢失资格。
有效参战判定来自服务端；不使用玩家在 HTTP 请求里自报的人数或伤害进行真实发放。原生资格检查仍有优先权，不绕过短局或无效参与者限制。

| 真人数 | 真人系数 | 基础十倍＋双倍的总系数 |
|---|---:|---:|
| 1 | 1 | 20 |
| 2 | 1.1 | 22 |
| 3 | 1.21 | 24.2 |
| 4 | 1.331 | 26.62 |
| 8 | 1.9487171 | 38.974342 |
| 12 | 2.85311670611 | 57.0623341222 |

默认完整奖励时长为 180 秒；不足时按有效参战秒数/180 折算，达到 180 秒后为一倍。
默认不足 30 秒不计奖。没有击杀仍保留有效参战保底，不能把“零人头”直接等同于挂机。
该时间规则用于避免极短对局速刷；它不代替游戏原生资格检查，也不把零击杀直接判为挂机。

## 已确认的首版默认值：均为一倍值

本次以以下值作为首版配置基线；基础倍率和各项奖励可由服主调整。AI 同档和真人每多一人
乘 1.1 是已确认的规则。调整预览配置不会自动改变当前游戏发币。

### 对战

| 项目 | GB | MB |
|---|---:|---:|
| 胜利保底 | 500 | 2 |
| 失败保底 | 300 | 1 |
| 平局保底 | 400 | 1.5 |
| 每次有效击杀 | 60 | 0.2 |
| 每次助攻 | 20 | 0.1 |
| 每 1,000 有效伤害 | 15 | 0.1 |
| 个人贡献合计上限 | 400 | 2 |
| MVP 额外奖励 | 200 | 6 |

MVP 奖励在贡献上限之外，再和其余金额一起乘全部倍率。AI 不拥有钱包；AI 获得战绩时
不会发币给虚构账号。真人是否为 MVP 应采用本局认可的结算结果，并要求有实际战斗贡献。
使用原生结算认可的 MVP，不另算一套与游戏画面不一致的排名。

### 任务

| 项目 | GB | MB |
|---|---:|---:|
| 通关保底 | 100 | 0 |
| 失败保底 | 35 | 0 |
| 每个小怪击杀 | 2 | 0 |
| 每个 Boss 的个人贡献折算 | 45 | 0.5 |
| 每 1,000 有效伤害 | 1 | 0 |
| 任务贡献合计上限 | 150 | 1.5 |
| 应用难度后一倍总额上限 | 300 | 2 |

难度：普通 ×1、困难 ×1.25、专家 ×1.5。任务不领取对战 MVP 奖励。
Boss 贡献按实际 HP 损失贡献分配，不只奖励最后一击：两个 Boss 各贡献一半，折算合计为 1。
同一 Boss 的全队折算合计不能大于 1；个人折算不得超过本局真正击破的 Boss 数。

## 同条件示例

以下均为有效参战 3 分钟、4 名真人、基础十倍、双倍时段。整数货币最终只取整一次。

| 场景 | 一倍 GB / MB | 最终 GB / MB |
|---|---:|---:|
| 普通任务：15 小怪、1 Boss 贡献、8,000 伤害 | 183 / 0.5 | 4,871 / 13 |
| 对战失败：2 击杀、6,000 伤害 | 510 / 2 | 13,576 / 53 |
| 对战胜利：3 击杀、8,000 伤害 | 800 / 3.4 | 21,296 / 90 |
| 同上且为 MVP | 1,000 / 9.4 | 26,620 / 250 |

这个典型对战胜利的 GB 约为任务的 4.37 倍，MVP 约为 5.46 倍；MB 差距更大。
这是同条件样本比较，不承诺每种极端任务与每种极端对战都满足固定倍数。

## 辅助入口的接入方式

新增“战斗奖励”模块，页面 `/rewards`、API `/api/rewards`：

- GET `/api/rewards`：配置、版本号、接入状态和会话 token。
- POST `/api/rewards/multiplier`：保存基础倍率，要求预期配置版本，避免覆盖另一处修改。
- POST `/api/rewards/policy`：保存完整规则。
- POST `/api/rewards/preview`：演算单场明细，可临时试算新倍率而不保存。

已经提供同端口挂载适配器，不改另一条正在开发的辅助主入口文件：

```python
from owner.rewards.workspace import Workspace
from assistant_modules.rewards import attach

# 在现有辅助 HTTP server 创建之后、serve_forever 之前调用。
attach(server, Workspace(owner_workspace / "battle-rewards"))
```

它保留原有模块路由，并在遵循现有 `json_response` 约定的 `/api/modules` 列表追加奖励入口。
真实 HTTP 测试验证了同端口挂载、原路由保留、会话 token/Origin 检查和配置版本保护。
服主可用[部署入口](battle-rewards.zh-CN.md#启动奖励工作器和辅助入口)装配已安装助手的同端口实例，保留原有模块；不对已经运行的 Python 进程做动态修改。

也可以独立打开设计预览，不启动游戏：

```powershell
python tools/reward_preview.py --workspace build/reward-preview --port 0
```

控制台会显示实际分配的本机端口。未收到有效原生/钱包心跳时，页面显示“未连接”；服务加载相同配置且钱包健康后才显示已连接。连接中的保存会发布给真实服务，因此请区分试算和保存。

## 倍率、双倍与旧十倍的边界

本模型独立定义“一倍金额”，不把当前已被放大的原生奖励表重新作为基数。
只读核对发现 `tbl_TeamExp`、`tbl_GridExp` 等按模式、人数和胜负提供基础值。例如当前
Team 表两人胜利 6,000、四人胜利 6,600；个人击杀和伤害不是这些表的字段。
现有 `Server_Event_ExpMultiplier.sql` 还会直接乘表值，不能凭现值反推它过去被改过几次。

原生实现采用以下结算边界：

1. 战斗结束收集经核对的胜负、击杀、有效伤害、助攻、Boss 贡献、MVP 和真人身份。
2. 对全场一次性读取配置版本与结算时的活动状态，所有玩家使用同一快照。
3. 双倍功能只提供本次活动系数 1 或 2；货币由本模型统一乘一次。不能再把金额送入另一个乘二的货币钩子。
4. 替换本局原生 GB 奖励字段，或统一接管其记账；不能先发旧 GB 再额外发一份完整新奖励。
5. GB、MB 使用同一结算身份和事务/回执体系，按“服务端实例＋本局 ID＋真实账号”去重。
6. MB 复用统一钱包发放机制，不冒充虚构道具掉落；服务器确认后再刷新客户端显示。

`model.preview_match` 提供离线批次计算契约：从唯一参战账号推导真人数、拒绝重复账号、检查
全场 Boss 贡献总额，并让所有人使用同一份配置/活动快照。该 Python 演算接口不执行记账；真实 Mod 和钱包工作器走独立的可信结算通路。

这个倍率用于战斗/任务货币，不隐含放大登录送币、手动补偿或充值。角色/机体经验继续由各自规则管理。
倍率配置变更影响后续结算快照，不修改已经发出的奖励。

## 原生实现与验证边界

- 原生有效 HP 损失入口统计实际伤害与死亡；PvP 击杀和排名读取当前结算帧，不把 Stars 当伤害。
- 普通任务模式 5/8/10 从 `BattlePilot+0x1CEC -> NpcData[0]` 读取 NPC 身份，按 `(MissionID,NpcDataID)` 与服主导出的 Boss 表匹配。AI 构造器中的 `BattleUnit+0` 不作为普通任务身份依据。
- GB 使用原生最终字段和原入账通路；MB 使用原生 GC 过程的持久去重封装，再发送已有现金余额消息。
- 框架/DLL 合成原生帧、独立双倍模块同载、真实 SQL 过程隔离库、真实 Agent BATTLE 转发和辅助入口均有可复现检查；真实认证对局及 HUD 验收单独保留。
- `objective` 是计算引擎的扩展字段，当前原生适配不提供该事件，默认置零且不计奖；不会把未验证的 Stars/排名点冒充目标事件。
- 原生 GB 字段是 16 位。默认十倍、十二名真人、双倍的极端单笔 GB 为 62,768；整套默认规则的安全基础倍率上限是 10.440894。超限配置拒绝加载并显示未就绪，不会截断金额。
