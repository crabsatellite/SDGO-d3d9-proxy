# 机库整理与重复机体兑换（Beta）

客户端 Mod `hangar_manager` 在游戏「机体管理」页的「机体锁定/解除」「机体解体」旁提供「一键整理」和「重复兑换」按钮。
它使用游戏原生的换槽、机体详情和拆解请求，不需要新的登录方式、HTTP 服务、SQL 凭据或服务器端 DLL。
朋友拿到同一份 Mod 和机体规则即可使用；服主只在修改了机体/拆解奖励时更新规则文件。

0.2.1 修复原生页按钮不能点击及随机红/绿色块：操作按钮使用旁边原生按钮的普通、悬停、
按下皮肤和文字样式。通过 Manager 导入修复增量包，关闭并重新启动目标客户端后生效；
本次更新无需重启服务器，也不需要重新分发账号或修改奖励规则。

0.2.2 将按钮、皮肤与文字的初始化全部完成后才显示入口；中途失败不显示半成品按钮，
也不拦截游戏原有的锁定/解体操作。皮肤直接取自当前客户端的原生按钮，玩家无需补素材或改配置。
新分发的客户端须包含本版 DLL 与配套符号；已运行的旧 DLL 需要正常关闭、更新、再启动后才会替换。

0.2.3 修复已加载却点击无响应：按原生应用状态编号识别大厅，不再读取大厅小对象中的战斗专用字段。
进入页面和点击动作会写入诊断日志；加载成功和真正收到点击是分别记录的。

0.2.4 修复整理后原生格子被隐藏、留下空白的问题。纯整理保持机体格子显示，整理期间同一按钮变为
「停止整理」；完成兑换后自动返回格子。进度与结果显示在机库下方，重复兑换的清单按原生右侧网格
位置排版。刷新补全原生的列表、图标、页框可见性三个步骤。0 笔表示可移动机体已符合排序规则。
本版只刷新当前机体管理页；大厅或房间的其他机库视图可能保留旧缓存，需要重新登录同步。

## 功能

- 一键按 S/A/B/C、子等级、机体编号、等级与实例编号整理可移动槽位。
- 锁定、出击中、舰队、租赁和未知机体保留原位；不会自动解锁或撤下舰队。
- 重复机体先向服务端逐台查询详情，再显示兑换清单。默认每种**相同状态**保留两台，
  已培养机体与不同涂装、技能、强化等状态分别保留。`KeepCopies` 可设为 1–20。
- 清单确认后，可选择原生 GB 或原生道具奖励（本版本通常为经验胶囊）。
  最终奖励以服务器的 `tbl_UnitGradeInfo` 和原生拆解过程为准。
- 道具使用原生拆解奖励/领取流程，不直接写入玩家仓库。
- 每次只发一笔修改，观察原生机库数据达到预期后再继续。成功后重绘当前机体管理页；其他视图需要重新登录同步。
- 无法确认回包、连接变化、机库被其他操作修改时停止；不会自动重试。状态不明后必须重新登录再操作。
  批次中已确认的原生操作不会回滚；停止只阻止后续请求。

原生协议使用稳定的 `UserUnitNumber`，不以「当前第几个格子」猜测要删除的机体。
预览和执行之间再次校验实例编号、槽位、保护状态与完整状态指纹。任何未知状态均不自动兑换。

## 安装

本 Mod 归入「玩法扩展」，标记为 Beta，仅安装到客户端。Full 框架包包含它，Base 包不包含；
可通过全局分类、`[features] hangar-manager=0` 或 `[mods] hangar_manager=0` 单独控制。
优先使用统一 Manager 的「导入客户端配置包」安装 Mod 增量包（`hangar-manager-0.2.0-manager.zip`）；
它仅包含本 Mod、规则、Manager 注册和符号增量，不覆盖核心或其他 Mod，不执行脚本。
完整框架包使用普通客户端安装脚本；下面的独立增量包安装方式保留已有核心和其他 Mod。

关闭**目标客户端**，解压本包后执行：

```powershell
powershell -ExecutionPolicy Bypass -File install_hangar.ps1 -GameDir "D:\Games\SDGO"
```

安装器只更新 `hangar_manager` 和它自己的符号节。已有核心、全局设置、其他 Mod 和它们的符号保留。
未装框架时，安装器会复用包内的基础框架安装脚本；已有图形代理由基础安装器串联。
已有 `mod.ini` 的设置和规则文件保留，`-RefreshRules` 可明确更新奖励预览规则。
支持的客户端为 `GOnline-54BE1568-00C97000`；不匹配的版本拒绝安装，签名冲突时核心不启用该 Mod。
本包不启动、停止或重启任何服务器，也不包含账号、真实机库、日志或连接密码。

正常启动游戏，进入「机体管理」页后使用按钮。兑换奖励选择、清单分页、两次确认及停止均在原游戏页内完成；
离开该页会取消旧预览，重新进入需要重新核对。没有独立桌面窗口、右上角悬浮工具条或 F8 入口，也不要求 Manager 常驻。
可在 `sdgo/sdgo.ini` 的 `[mods]` 中设置 `hangar_manager=0` 禁用。

## 配置

日常保留份数与兑换后整理偏好在统一 Mod Manager 调整。底层配置为 `sdgo/mods/hangar_manager/mod.ini`：

| 设置 | 默认值 | 含义 |
|---|---|---|
| `KeepCopies` | 2 | 每种相同状态的未培养机体保留数量 |
| `SortAfterExchange` | 1 | 兑换后整理可移动机体 |
| `RequestIntervalMs` | 150 | 原生请求最小间隔 |
| `ReplyTimeoutMs` | 10000 | 等待数据同步的最长时间 |
| `MaxSlots` | 1200 | 原生服务端已核对的可移动槽位上限 |
| `RulesFile` | units.tsv | 相对本 Mod 目录的机体/奖励预览表 |

所有路径相对 Mod，不写入个人电脑路径。未知机体不参与兑换，排序时也保留原位。
规则文件只决定显示和客户端筛选，不能提高服务器发放的奖励。
服务器变更规则后，服主可只读导出：

```powershell
python export_hangar_rules.py --server-ini "D:\Server\StoreServer.ini" --output units.tsv
```

该宿主工具需要已有 SQL ODBC 驱动及 `pyodbc`；玩家运行 Mod 不需要 Python。
也可用 `--snapshot` 读取配置表 JSON。导出只查询机体、等级奖励和奖励名称配置，不导出用户信息。

## 实现与验证边界

原生发送点已从本地客户端字节与保留反编译核对：

- 换槽 `0x0800`，26 字节，携带两个稳定实例 ID 与目标槽位。
- 拆解 `0x06D2`，19 字节，奖励选择 1 为 GB、2 为道具；服务端再次检查所属、锁定、出击和舰队状态。
- 详情 `0x078B`，14 字节；预览等待原生完整详情写入再继续。
- 排序没有直接改数据库；每一笔由原生回包更新 `CUnitInfo`，观察结果一致后才追加下一笔。

操作完成或返回机库时只重绘原生机库界面，不冒充从服务器重载全库。登录时的整库请求实际上按实例 ID
增量分页，直接重复调用不会可靠地清除旧数据，因此本版本不强行重建整个客户端缓存。
原生换槽/拆解的逐笔确认路径支持实时同步；无法确认时明确要求重新登录。

自动检查覆盖随机排列排序、锁定/出击/舰队/租赁保护、状态变体保留、唯一机体保留、
确认前无兑换、原生字节布局、取消、拒绝、超时、连接变化，以及生产代码的合成原生适配器。
新版还覆盖宿主分配的原生子控件、页内布局边界、清单分页、两次确认、关闭失效、原控件可见性恢复和布局不匹配拒绝接入。
0.2.1 额外使用本地客户端两段已校验的原生代码，复现空按钮故障并检查鼠标移入、按下、
松开、移出和禁用状态；命中区域、焦点、事件接收和绘图接口使用合成替身，不启动游戏或联网。
这些不是玩家账号的实战证明。首次真人验收先检查按钮与页内文字，再测试纯排序，用已核对的普通重复机体验证两种奖励。
本任务不自动对真实机库执行整理或兑换。

构建：`cmake -S . -B build/hangar -G "Visual Studio 17 2022" -A Win32`，
随后 `cmake --build build/hangar --config Release`。
测试：`ctest --test-dir build/hangar -C Release --output-on-failure`。
原生鼠标回放需配置 `-DSDGO_HANGAR_NATIVE_HOST="D:/Games/SDGO/GOnline.exe"`，
构建 `hangar_native_input_test` 后执行 `ctest --test-dir build/hangar -C Release -R hangar_native_input_replay --output-on-failure`。
