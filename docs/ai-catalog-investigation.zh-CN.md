# AI 全机体扩充调查与当前状态

调查日期：2026-11-01。独立分支 `feature/ai-unit-catalog`；没有修改或重启原客户端、游戏服务、数据库。

## 结论

当前数据库提供了较大的候选范围，编号范围也有容量。实现全机体 AI 池需要服务端与客户端配套，
不能只运行一个 `INSERT tbl_NpcData` 脚本。当前已实现独立的 `ai_catalog` 双端 Mod、
服主目录生成、安装/开关/恢复和玩家导出，详见[使用指南](ai-catalog.zh-CN.md)。
它通过进程内记录实现扩充，无需向游戏数据库写入 NPC 行。实际游戏表现仍待用户手动验收。

## 本地证据

读取现有目录 JSON，另用隔离 SQL 实例做固定目录 `SELECT` 核对；不使用玩家账号、机库等表。
配套客户端数据从已有提取的 GDT 核查，未改原游戏包。

| 项目 | 结果 |
|---|---:|
| `tbl_Units` 玩家机体记录 | 1071 |
| `SallyReady=1` 且 HP>0 的候选 | 819 |
| 未标记可出击而跳过的记录 | 252 |
| 现有 AI NPC（3604001–3607000） | 30 |
| 未占用 NPC 编号（同时排除已读取的客户端 NPC） | 2970 |
| 候选缺失客户端机体/直接变形引用 | 0 |
| 候选缺失已声明武器编号 | 0 |
| 候选在服务端 `tbl_UnitNpc` 中缺项 | 819 |
| 至少一个武器槽为空的候选 | 58 |

这里的“候选”不等于 AI 兼容性通过：同一机体的独立出击与变形关系、技能和 AI 武器选择仍需要验证。
现有 30 个 AI NPC 在服务端、客户端的机体 ID / HP 引用核对一致。

默认 LV 分组为 177 / 239 / 237 / 107 / 59 个。
如直接用单行 `LevelN=` 表达，五行的值分别为 1415 / 1911 / 1895 / 855 / 471 字节，
前三行超过现有两个服务端 AI Mod 的 1024 字节读取缓冲区，会截断。
不能通过生成更长配置来绕过这个限制。

## 源码与数据对应

* `mods/coop_ai/coop_ai.cpp` 和 `mods/pvp_ai/pvp_ai.cpp`：从服务端 AI-NPC 列表过滤 `LevelN`，
  使用 `battle.build_ai_pilot` 生成参战者；池子是 NPC ID，不能直接换成 `tbl_Units.UnitNumber`。
* `mods/coop_ai/mod.ini`、`mods/pvp_ai/mod.ini`：现有池共 30 个原版 AI NPC，LV4/LV5 为同一批。
* `docs/coop-wingmen.zh-CN.md`：已有的新增 NPC 三方对应要求。
* `GOnlineGame.dbo.tbl_NpcData`：NPC 使用的机体、HP 等数据，没有客户端的 AI 脚本名。
* 客户端 GDT `0198`：30 条 598 字节的 AI NPC 记录，`+0x69` 是机体 ID，
  `+0x6D` 是 AI 脚本名，`+0xE5` 是 HP。
* 已有 GOnline 反编译导出 `FUN_00414090`：按顺序将 `0237/0242/0243/0244/0246/0245`
  作为 type 2 机体数据加载，将 `0020/0105/0128/0162/0198/0222` 作为 type 41 NPC 数据加载。
  `FUN_004230D0` 解析 598 字节 NPC 记录并跳过非零 security level 的记录。
  这是历史静态导出和本次离线数据核对，不是游戏执行证据。

本次另用 REA / Ghidra 静态核对实际 `BattleServer.exe` 的 `0x00485720`：先按 NPC ID
查记录，再按其机体 ID 查数据，任一步缺失均返回失败，随后还读取机体的武器/技能引用。
Evidence：`ev_51d5d3672f23a7233a21ea913bcfdd97a36940bdfb517f94a96d3d912426479c`；
目标 SHA256：`f74d16037fc8f4fe49a8041488aabd1948df1b1a9f2d125de9dad4a2347b63a4`。
这支持配套数据检查的必要性，不证明普通机体已能由 AI 使用，也没有仅凭该函数断言数据库加载表名。

## 实现与保留边界

独立客户端 Mod 提供目录声明的新 NPC 记录；服务端只在扩展 AI 的构造上下文中使用私有机体副本。
双方共用版本化二进制目录，等级池通过可选 provider 取得，绕过单行 INI 长度限制。
未加载此 Mod 时，现有 AI Mod 的 `LevelN` 读取与原生名单过滤继续工作。

生成器按武器类型、等级与 HP 选原生脚本，允许服主覆盖；这不证明所有特殊武器、技能、变形和模型兼容。
安装器记录首次安装前的文件并支持卸载恢复，更新后关闭状态保留；受管文件被其他更新器修改时拒绝覆盖。
运行时的原生 ID 冲突保留原记录，源数据不一致的扩展条目拒绝使用。

可选原生测试在调用方提供的 BattleServer 副本中，使用自有的 map/record/buffer 调用实际 `BuildAiPilot`，
819 个候选通过，共 4117 项检查。该测试不执行游戏主程序，不启动网络或 SQL，不是实际对局证据。
两端 DLL 的真实 core 集成和文件安装恢复另有自动测试；原客户端、原数据库和运行中的服务均未部署本 Mod。
